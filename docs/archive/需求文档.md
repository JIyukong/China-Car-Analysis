## 一、项目定位

### 1.1 项目目标

项目面向汽车行业投资分析场景，目标是把销量、股价及相关维度整理成一套可持续更新、可用于 BI 消费的数据底座。

### 1.2 当前诚实定位

当前项目的真实定位不是“完整多因子投资平台”，而是：

> 以销量因子为主链、以股价因子为下一阶段补齐目标的数据分析底座项目。

目前真正落地的部分集中在：

- 16888 销量主链
- AKShare A 股 / H 股日线与 A 股财务采集
- 同花顺行业指数 881125 汽车整车基准线
- 商品期货主力连续日线（碳酸锂/铜/铝）金属 BOM 成本基准
- 云 MySQL 数仓
- 维度建模
- DWD 清洗（销量明细、销量城市、股票日线、股票财务）
- 部分 DWS 聚合
- FastAPI 健康检查与调度框架

尚未落地但已明确方向的部分：

- 调度服务生产环境连续运行验证（调度链路代码已全量注册）
- Power BI 报表资产
- Publish to Web 发布链

### 1.3 产品调性

- 客观：强调数据事实，不输出主观投顾结论
- 工程化：优先保证链路可跑、模型可维护、口径可追溯
- 可扩展：允许后续逐步接入更多投资因子

### 4.2 销量链路真实来源

当前销量链不再依赖 AKShare，真实来源是项目内已经抓取并保存下来的文件：

- `pipelines/ingest/sales/crawl_16888_style/data`
- `pipelines/ingest/sales/crawl_16888_city/data`

文件中的核心字段分别覆盖：

- style：`month`、`rank`、`model_name`、`sales_volume`、`manufacturer`、`price_range`
- city：`month`、`rank`、`model_name`、`city`、`sales_volume`、`level`、`price_range`

### 4.3 股价链路当前来源

当前股价链路采用 AKShare，范围限定为 A 股与 H 股：

- A 股日线主源：`stock_zh_a_hist`
- A 股日线备援：`stock_zh_a_hist_tx`、`stock_zh_a_daily`
- H 股日线主源：`stock_hk_hist`
- H 股日线备援：`stock_hk_daily`
- A 股财务数据源：`stock_profit_sheet_by_report_em`

当前范围明确不包含 US 日线采集与 US 财务数据采集：

- `stock_us_hist` 不纳入当前需求范围
- 美股财务数据不在当前采集范围内，`ods_stock_finance` 采集脚本显式跳过 market=US 的股票
- 如后续恢复 US 采集，需单独评审网络链路、字段口径与数据完整性规则

### 4.4 指数基准链路当前来源

当前指数基准链路采用 AKShare 同花顺行业指数接口，首期只覆盖 881125 汽车整车：

- 主源：`ak.stock_board_industry_index_ths(symbol="汽车整车", start_date, end_date)`
- 范围：首期仅 881125 汽车整车（`index_source='THS'`）
- 起始日期：默认 `20170101`，与股票日线对齐，便于时序对齐分析
- 增量策略：以 `ods_index_daily.trade_date` 最大值为增量起点，首次为全量
- 扩展性：`dim_index` 预留 `THS/CSINDEX/WIND/OTHER` 编制来源，后续可追加中证/万得等基准指数

### 4.5 商品期货成本基准链路

整车股价周期的本质是“盈利预期 × 估值倍数”，而盈利 = 收入 − 成本 − 费用。金属 BOM 是新能源整车成本端的核心驱动：

- **碳酸锂（LC0）**：动力电池正极核心，占纯电 BOM 约 15–25%（GFEX，2023-07-21 上市）
- **铜（CU0）**：电机绕组、线束、充电桩核心材料（SHFE，1999 年上市）
- **铝（AL0）**：车身轻量化、电池托盘核心材料（SHFE，1999 年上市）

当前商品期货链路采用 AKShare 新浪主力连续接口：

- 主源：`ak.futures_main_sina(symbol="LC0"/"CU0"/"AL0", start_date, end_date)`
- 主力连续由新浪按每日成交量/持仓量自动拼接，消除单合约到期断层
- 范围：首期仅国内三大金属品种主力连续，不含期权、不含外盘 LME
- 起始：铜铝 1999 年起，碳酸锂 2023-07-21 上市起
- 增量策略：以 `ods_futures_daily.trade_date` 最大值为增量起点
- 期货特有字段：`open_interest`（持仓量）、`settle`（动态结算价）
- 扩展性：`dim_commodity` 与 `dim_stock` 平级，未来可加入钢材、稀土、原油等其他 BOM 品种

### 4.6 粒度对齐原则

项目长期目标是做“销量 × 股价”关联分析，因此必须保留以下口径：

- 销量按月
- 股价按日
- 关联分析时需要有月度对齐规则

后续默认支持两种对齐方式：

| 对齐方式 | 含义 |
|----------|------|
| 月末收盘价 | 取该月最后一个交易日收盘价 |
| 月均成交量加权价 | 取该月全交易日成交量加权均价 |

多市场上市时，默认以 `bridge_company_stock.primary_market` 为主口径。

## 六、数据库与数仓设计

### 6.1 设计原则

- 上市公司主体与销量主机厂主体分开建模
- ODS 只保留原始事实，不人为提前汇总
- 维度派生尽量从主链数据自动生成
- 手工 CSV 数据单独走权威存储表，避免被派生表覆盖

### 6.2 核心维度与桥接

当前核心主数据结构如下：

- `dim_company`：上市公司主体
- `dim_oem`：销量主机厂主体
- `dim_brand`：品牌主体
- `dim_model`：车型主体
- `dim_date`：日期维度
- `dim_stock`：股票维度
- `dim_index`：指数维度（首期覆盖同花顺行业指数）
- `dim_commodity`：商品期货品种维度（首期碳酸锂/铜/铝）
- `bridge_brand_oem`
- `bridge_company_stock`

### 6.3 ODS 层

当前已落地：

- `ods_sales_monthly_model`
- `ods_sales_monthly_model_city`
- `ods_stock_daily`
- `ods_stock_finance`
- `ods_index_daily`
- `ods_futures_daily`

说明：

- ODS 层定位为"忠实落地源数据"，只保留原始事实，不做提前汇总或维度强约束
- 因此 `ods_stock_daily` / `ods_stock_finance` 不再强制外键约束到 `dim_stock`，`stock_id` 允许为空
- ODS 同时保留原始自然键快照字段（`stock_code_raw`、`stock_name_raw`、`market_raw`、`exchange_raw`、`source_symbol`）以支持回放与追溯
- `ods_stock_daily` 唯一键采用自然键组合：`uk_stock_code_date (stock_code_raw, trade_date, source)`
- `ods_stock_finance` 唯一键采用自然键组合：`uk_stock_code_report (stock_code_raw, report_date, report_type)`
- `stock_id` 由采集脚本在写入时尽力映射，仅作为下游便利索引使用
- 未映射到维度的原始数据允许先落入 ODS，由 DWD 层负责映射与清洗
- `ods_stock_finance` 当前仅采集 A 股财务数据，美股（US）显式不采集，港股暂不支持
- US 日线当前显式不采集
- 城市 ODS 不直接补品牌 / 主机厂，以原始文本为主
- `ods_index_daily` 唯一键采用自然键组合：`uk_index_code_date (index_code_raw, trade_date, source)`；`index_id` 允许为空，由采集脚本尽力映射
- `ods_futures_daily` 唯一键采用自然键组合：`uk_commodity_date (commodity_code_raw, trade_date, source, contract_type)`；含期货特有字段 `open_interest`（持仓量）、`settle`（结算价）；`commodity_id` 允许为空，由采集脚本尽力映射

### 6.4 DWD 层

当前已落地：

- `dwd_sales_monthly_model`
- `dwd_sales_monthly_model_city`
- `dwd_stock_daily`
- `dwd_stock_finance`

当前销量 DWD 清洗规则：

1. 按 `row_hash` 去重
2. 标准化车型名与厂商名
3. 解析价格区间
4. 关联 `dim_model`、`dim_oem`、`dim_company`
5. 排除异常销量

当前股票 DWD 清洗规则：

1. 从 ODS 自然键快照映射 `stock_id`
2. 统一 A 股 / H 股口径字段
3. 财务表按 `report_date + report_type` 去重

### 6.5 DWS 层

当前已落地：

- `dws_sales_monthly_company`
- `dws_sales_monthly_brand`

当前状态说明：

- DWS 脚本已存在
- DWS 表也已存在
- 但默认初始化链和调度链都未自动跑它

### 6.6 手工维度支线

当前已落地：

- `dim_energy_vehicle`
- `dim_model_ads_manual`
- `dim_model_ads_zipper`
- `dim_area`
- `dim_car_level`

设计目的：

- 将人工维护数据与自动派生数据分离
- 保证尚未上市或尚未进入主链的车型信息也能被记录
- `dim_area` 为销量城市维度补齐大区 / 省 / 地级市三级映射

## 八、非功能要求

### 8.1 可维护性

- 所有主链脚本必须可独立执行
- 文档必须与真实文件路径一致
- 手工维度必须保留原始 CSV 溯源能力

### 8.2 可追溯性

- ODS 保留 `source_file`、`source_url`、`fetch_time`、`row_hash`
- 手工维度保留原始 CSV 字段和权威存储表

### 8.3 安全与访问

- Power BI 只读账号仅授予 `SELECT`
- 云 MySQL 需启用白名单与强密码
- Publish to Web 属于公开分享，未来若启用需接受公开数据边界

### 8.4 性能边界

当前性能目标以单人开发、单项目运行稳定为主：

- 健康检查可快速返回
- 初始化与月度批处理可稳定完成
- 不以高并发在线服务为目标

## 十一、决策摘要

1. 当前项目以代码现状为准，不夸大未实现能力
2. 销量主链采用 16888 已落地文件，不再把 AKShare 写成销量来源
3. 股价链路采用 AKShare，当前只抓取 A 股和 H 股；US 数据不在当前范围
4. FastAPI 当前定位是健康检查与调度支撑，不是查询 API 层
5. Power BI 是后续主消费端，但当前还未形成交付物
6. 手工维度必须与自动派生链解耦，避免被覆盖
