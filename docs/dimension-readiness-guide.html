手工维度缺失治理 · 流程与操作手册

dim_energy_vehicle.csv / dim_model_ads_matched.csv 缺失时的自动发现、告警、阻断与补维恢复

一、机制一句话说明

调度链路跑到 DWD 清洗 / DWS 聚合前，会自动统计 5 项维度的缺失率。 一旦超过阈值，系统会立刻给飞书/钉钉发一条带补维清单的告警， 同时暂停后续链路（记 skipped，不产生脏数据）。 你照清单补完两个 CSV，无需手动重跑——次日 cron 会自动重探并恢复。

必填项零容忍 energy_type（能源类型）是必填项，缺 1 个就告警并阻断； 其余项（vehicle_type / ads / area / vehicle_subtype）默认阈值 5%。

三、检查项与对应手工表

检查项缺失判定对应手工 CSV阈值
energy_type 能源类型 = '占位' dim_energy_vehicle.csv 0（缺1即报）

area 地区 area_id IS NULL dim_area.csv（20年不变） 5%
vehicle_subtype 级别 vehicle_subtype_id IS NULL 级别字典 5%

四、首次配置：打开飞书/钉钉告警（只需做一次）

在群里添加机器人

飞书：群设置 → 群机器人 → 添加 → 自定义机器人，复制 Webhook 地址。

钉钉：群设置 → 智能群助手 → 添加机器人 → 自定义，安全设置勾选 “自定义关键词”并填 CarApp（告警正文含此词，免加签），复制 Webhook。

填写项目 .env

在项目根目录 .env 追加（飞书）：

ALERT_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxxx
ALERT_WEBHOOK_TYPE=feishu

钉钉则把 TYPE 改成 wecom（钉钉文本格式与企业微信一致，无需改代码）：

ALERT_WEBHOOK_URL=https://oapi.dingtalk.com/robot/send?access_token=xxxx
ALERT_WEBHOOK_TYPE=wecom

重启调度器

配置在进程启动时读取，重启调度服务后生效。未配置 URL 时只写日志、不推送。

防刷屏 同一条维度告警按“任务+月份”去重，10 分钟内只推一次；补完维次日重跑通过后会再推一条“已恢复成功”。

五、收到告警后的操作步骤

看告警正文，确认缺哪项、缺哪些车型

告警里直接带了“维度就绪报告”和“待补维清单”，长这样：

维度就绪报告 (目标月模型数: 320)
  energy_type 占位: 1 (99.69%)
  ads 缺失: 1 (99.69%)
状态: 未就绪

# dim_energy_vehicle.csv 待补（model_name,energy_type,vehicle_type）
阿维塔06T,,
# dim_model_ads_matched.csv 待补
阿维塔06T,,,,

打开对应 CSV 补行

能源/车型缺 → 编辑 data/manual_dimensions/dim_energy_vehicle.csv，填 model_name,energy_type,vehicle_type。

ads 缺 → 编辑 data/manual_dimensions/dim_model_ads_matched.csv，填 model_name,ads_proportion,ads_supplier,ads_supplier_mode,上市时间。

把清单里的空行补全真实值即可，注意 model_name 要和清单完全一致（含空格）。

保存 CSV，剩下的交给调度器

不用手动重跑、不用重启。第二天 cron 窗口（style 12~15号 03:00 / city 20~25号 03:30） 会自动重跑 build_dimensions → refresh_ads → run_dwd_clean， 重新加载你补的 CSV。

确认恢复

重跑通过后，你会收到第二条“任务已恢复成功”的通知，DWD/DWS 继续往下生成。完成。

想当天就验证，不等次日？ 可手动触发（确保已连库）： 
python -c "from scheduler.jobs.etl_jobs import run_dwd_clean; run_dwd_clean('2026-07')"
把 2026-07 换成目标月。补完 CSV 后执行即可立即重跑该门控点。

六、端到端时间线示例

每月12号 03:00 — style 链启动，跑到 run_dwd_clean 发现 ads 缺 12% > 5%
↓
03:00 即刻 — 日志写入补维清单 + 飞书/钉钉响铃，链路 paused（skipped）
↓
你看到通知 — 把缺的车型加进两个 CSV 并保存
↓
次日13号 03:00 — cron 重探，CSV 已加载，门控通过 → lifecycle + dws_agg 继续，收到“恢复成功”
