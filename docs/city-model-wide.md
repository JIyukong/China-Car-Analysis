# 城市车型宽维表与切换方案

正式库结构由管理员单独部署；ETL 不执行建表或迁移文件。部署后先核对结构与运行账号，
再通过统一入口按已验收月份增量发布。代码更新本身不会启用开关或回填历史。

## 数据模型

`dim_city_model` 一行表示一个城市来源车型身份，业务键为 `(source, source_model_name)`。
来源车型名仅去首尾空白，保留括号、“进口”等标记。品牌、主机厂编码和名称直接
保存在同一行，不关联全国车型、品牌、主机厂或上市公司 ID，不另外拆城市品牌和主机厂表。
同名且来源不能消歧的车型不擅自拆分销量；全国候选冲突保留为 conflict。

城市 ODS 为车型发现的完整来源。全国 ODS 同名记录优先提供厂商候选，并参考已有
品牌主机厂桥接获取品牌候选；只读取统计月及以前的数据，不依赖全国 DWD 是否发布。
全国信息不是已审核归属，不会覆盖人工确认字段。城市独有车型同样建档，候选为空。
候选桥接使用当前关系，仅供审核参考，不代表历史生产归属。

新表初次使用时所有车型归属从待确认开始，不批量沿用旧维度的已确认状态。
因此首次发布可能产生数百条城市审核待办，不能把现有81项当作新流程的待办总数。
这些待办不阻断销量入库；应按销量占比和进口/同名冲突优先审核。

名称含“进口”自动标记 imported，其余 unknown，不能凭没有进口字样判定国产。
进口渠道默认 unknown，只有提供证据后才填写 official 或 parallel。
名称疑似变化但没有可靠源ID时不自动合并，例如“宝马2系(进口)”与“宝马2系”。

`dwd_sales_monthly_city` 是新增城市明细表，通过 `city_model_id` 关联宽维表。
旧 `dwd_sales_monthly_model_city` 和已有全国维度不修改、不回填。
保留独立事实表是因为旧表强制要求全国模型及公司ID，直接切换会触发非空约束。
城市明细仍要求地区和车辆级别匹配；归属待确认不阻断销量发布。
首次/最后出现与活跃状态按已发布城市明细计算，不读取全国生命周期。

## 人工审核

未确认车型通过现有飞书待办生成 `city_model` 类型，业务键为完整来源车型名。
人工填写的字段如下；所有字段必须齐全，不填写公司信息：

```json
{
  "brand_code": "CITY_BRAND_EXAMPLE",
  "brand_name": "已核实品牌",
  "oem_code": "CITY_OEM_EXAMPLE",
  "oem_name": "已核实生产企业",
  "production_type": "imported",
  "import_channel": "unknown",
  "energy_type": "燃油",
  "vehicle_type": "SUV",
  "evidence": "核实依据、链接或文件定位及适用范围"
}
```

production_type 可选 domestic/imported/unknown，import_channel 可选
official/parallel/unknown；非 imported 只能填写 unknown 渠道。
含进口字样的来源名称不能审核为 domestic 或 unknown。
品牌、主机厂必须填写真实值，不能用 OTHER 或占位值通过审核；代码和名称在已确认行中
保持一一对应。填写完整后标记 confirmed，受影响的城市月份自动进入复核队列。
若生产企业无法确认，保留 pending，销量仍存在；不能创建虚构生产企业凑齐字段。

这是当前属性宽表，不是历史拉链表；一次审核适用于该完整来源名称的全部月份。
存在随时间变化的生产归属时，先保留待确认，不应用一个当前归属覆盖历史。
未确认值由查询视图显式标记“归属待确认”。品牌统计包含已确认进口车型，国内厂商
统计应明确筛选 production_type='domestic'；不能用品牌是否合资推断生产归属。
候选不会直接参与品牌或主机厂归属统计。

## 管理员切换步骤（本次未执行）

1. 在独立测试库审阅并部署 `db/migrations/009_city_model_wide.sql`，验证字段及排序规则。
   正式部署由管理员另行操作，给ETL正常读写权限，给BI查询视图及基表的只读权限。
2. 保持 `ETL_CITY_WIDE_ENABLED=false`。先确认来源验收版本和首批待处理月份。
   此开关只隔离新增功能，关闭时既有城市链仍按旧逻辑运行，不等于暂停现有调度。
3. 用户决定数据处理范围后，在运行主机启用开关并重启服务。先选择一个来源已验收月份，
   使用 `python -m scheduler.runner --chain city --period YYYY-MM --resume`。
   来源错误月份不能使用 resume 绕过，仍需重新采集并验收来源。
4. 检查新表销量与正销量 ODS 一致、待确认占比、国产/进口独立、重复续跑幂等及失败回滚。
   切换前已经发布的历史月份不会因开关自动重建，必须显式逐月安排续跑。
5. 已有 city ownership 待办在新发布后由 city_model 待办替代；旧飞书记录保留为审计历史，
   不再用旧记录维护城市专属归属。全国 ownership 待办仍使用原流程。
6. BI 切换到 `vw_sales_monthly_city_wide`；不要把新旧城市事实表 UNION 相加。
   全国销量与城市销量分别展示，不把二者相加。

回退时关闭开关并重启服务，同时将BI切回旧城市数据源。新数据保留，旧表未跟随新链更新，
因此切回可能回到较早的数据版本；必须展示各自数据截至月份。
缺少新结构时启用开关会报发布错误，不自动建表，也不静默退回旧归属逻辑。

## 本地核查预览

无需数据库凭据，可先生成全量本地清单或单月清单：

```powershell
python -m scheduler.runner --chain city --preview-city-models logs/city-model-preview/all-local
python -m scheduler.runner --chain city --period 2026-09 --preview-city-models logs/city-model-preview/2026-09
```

输出 `summary.json` 保存各文件路径、内容摘要、manifest校验结果、重复键及非法行信息；
`models.csv` 保存车型、出现月份、进口标记、同月无标记车型以及全国厂商候选。
新输出在 `logs/` 中，不提交本地业务数据到仓库。

通过manifest校验的候选与缺凭据/校验失败的候选分开，后者仅供排查。
零销量车型纳入清单；重复键或非法行文件不参与车型或销量汇总。存在这类城市文件时，
全范围销量汇总返回空值，避免把被排除文件当作零销量。来源未出现不等于数据库不存在。
本地CSV校验通过也不代表正式ODS已接收，发布仍必须核对已验收版本摘要。

## 运行账号交接

结构部署完成不代表日常账号已配置。若当前 `.env` 使用管理员或目标库拥有
`ALL PRIVILEGES` 的维护账号，应由管理员在独立会话创建专用运行账号，
按 [调度和ETL](scheduler_guide.md#mysql-账号) 的权限模板授予目标库
`SELECT`、`INSERT`、`UPDATE`、`CREATE TEMPORARY TABLES`。
新城市发布不需要额外的建表、删表、改表或授权权限。
旧存储过程只在确需兼容调用时单独授权 `EXECUTE`，不授予全库管理权限。

管理员将新账号配置到本地 `.env` 的 `DB_USER`、`DB_PASSWORD`，不在聊天、
报告或仓库中保存密码。当前运行中的调度进程不会自动刷新缓存配置，
应等其活跃子任务结束后再受控重启，避免新旧账号混用。

## 验证

测试只使用 SQLite、临时文件和模拟连接。提交前必须通过
`python -m scheduler.runner --plan` 和 `python -m pytest`。
MySQL结构部署、BI权限及真实来源归属仍需管理员和维护人员按上述步骤验收。
